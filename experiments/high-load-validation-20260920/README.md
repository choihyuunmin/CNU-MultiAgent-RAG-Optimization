# 고부하 검증 (2026-09-20): 직접 실행, 동시 사용자 20·50·100명 × 4라운드

동시 사용자 4명에서 규약의 5% 기준을 통과하지 못한 직접 실행(검사된 직접 실행 어댑터)을
규약의 주 부하(100명)와 그 아래 두 단계(20·50명)에서 같은 200문항, 네 라운드로 다시 잰
결과다. 조건은 두 가지다.

- **original**: 검색 도구 호출을 모델이 다시 쓰는 원래 경로.
- **direct**: 준비된 검색 인자를 검사한 뒤 같은 처리기로 직접 실행(`try_typed_single_tool_dispatch`).

모델, 프롬프트, 서빙 옵션은 같다. 부하를 걸기 위해 실험용 인스턴스의 동시 처리 한도만 100으로
올렸다(이전 부하 실험과 동일). 요청 4,800건 모두 정상 응답했다.

- 주 부하 100명에서는 요청당 4.7초(2.9%) 빨라졌고 네 라운드 모두 같은 방향이다(+7.1, +0.9,

- 20명과 50명에서는 이득이 없다. 제거된 재작성 호출이 갈래당 20명에서 3.7–4.7초, 50명에서
  14–22초에 이르는데도 종단 응답시간은 줄지 않았다.
- 이유는 병목이 오케스트레이터 엔진이기 때문이다. direct 조건에서는 요청이 재작성 대기 없이
  오케스트레이터 단계에 더 빨리 도달해 그 엔진에 동시에 머무는 요청이 늘고(50명: 14.5 → 19.4,
  100명: 20.3 → 24.4), 호출 하나의 시간이 길어진다(50명: 28.1 → 33.6초, 100명: 38.3 → 42.2초).
  작업자 엔진에서 아낀 시간이 오케스트레이터 대기열로 옮겨 가는 구조다.
- 규약 게이트(`performance_gate`)는 통과하지 않는다. 주 부하 이득 하한 미달, 20·50명의 p95 비율
  상한 1.05 초과, 부하 1·2·5·10 미측정, 독립 품질 평가 없음이 사유다.

## 설계

| 항목 | 값 |
|---|---|
| 문항 | 고정 200문항(sha256 `c461780d…`), 이전 검증과 동일 |
| 부하 | 동시 사용자 20, 50, 100 (닫힌 루프, 부하별 순차 실행) |
| 라운드 | 부하마다 4라운드, 순서 original→direct / direct→original 교대 |
| 요청 수 | 본실험 4,800 + 예비 2 |
| 시간 제한 | 요청당 600초 |
| 유휴 조건 | 셀 시작 전 모든 엔진 waiting=0, running≤1 (실제 대기 1초) |
| 인스턴스 | 조건마다 별도 Pod(2 CPU / 8 GiB, 동시 처리 한도 100), 클라이언트 Pod 1개, 공유 vLLM 엔진 |
| 코드 | 패키지 커밋 `6632b0c`(adapter.zip sha256 `7ce897c6…`), 스크립트 해시는 `review-inventory.json` |

## 앞선 부하 실험과의 관계

2026-09-17/18의 2라운드 부하 실험은 64·100명에서 +3.5·+3.7초를 보고했다. 이번 4라운드 결과는
100명에서 +4.7초로 그와 같은 크기지만, 50명에서는 앞선 실험(−3.4초, 32명)과 마찬가지로
이득이 없다. 부하가 커질수록 이득이 커진다는 앞선 해석은 유지되지 않으며, 이득은 오케스트레이터
포화의 정도에 따라 0에서 3% 사이를 오간다.

## 판단

- 직접 실행은 검색 갈래의 재작성 호출과 작업자 엔진 부하를 확실히 제거하지만, 이 시스템에서
  종단 응답시간 이득은 어떤 부하에서도 3%를 넘지 않는다. 규약 기준(주 부하 평균 이득 하한 5%)에
  미달하므로 방출 기준으로는 채택할 수 없다.
- 남는 병목은 오케스트레이터 엔진의 처리 용량이다. 응답시간을 실제로 줄이려면 그 엔진의 호출 수나
  호출당 비용을 줄여야 하며, 검색 갈래 쪽 개선은 그 뒤에야 종단 이득으로 이어진다.

## 파일

- `analysis.json`, `analysis.requests.csv`: 분석 결과와 요청별 응답시간·갈래 수(문항 ID와 수치만).
- `protocol.json`, `status.json`, `smoke-status.json`: 클라이언트가 기록한 규약과 진행 상태.
- `review-inventory.json`: 패키지·스크립트·응용 소스 해시.
- `harness/`: 서버 진입점(`serve_hl.py`), 부착(`review_dispatch_attachment.py`), 부하 클라이언트
  (`run_sweep_trial.py`), 매니페스트 생성, 원격 감독, 분석 스크립트.
- 원자료(응답 본문, Pod 로그)는 저장소에 두지 않는다.
