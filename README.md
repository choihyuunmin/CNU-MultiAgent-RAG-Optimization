# Multi-Agent RAG Optimization

멀티에이전트 RAG(검색 증강 생성) 시스템의 응답 지연을 줄이기 위한 Python 어댑터와 실험 도구를 개발하는 프로젝트입니다. 에이전트의 작업 의존성, 모델 호출 대기, 스트리밍 전송을 관측하고 실행 방식과 추론 가속 기법을 비교합니다.

## 주요 기능

- **의존성 기반 실행**: 작업마다 필요한 선행 작업을 지정하고, 해당 작업이 끝나면 후속 작업을 바로 시작합니다. 서로 독립적인 작업은 병렬로 실행하고 결과가 필요한 지점에서 합칩니다.
- **스트리밍 전송 관리**: 모델 응답을 읽는 작업과 사용자에게 전달하는 작업을 분리하고, 크기가 제한된 버퍼로 연결합니다. 스트림 종료·오류·취소를 함께 처리합니다.
- **참조 ID 축약·복원**: 모델에 전달하는 긴 문서 ID를 짧은 번호로 바꾸고, 모델이 선택한 번호를 원래 ID로 복원합니다. 적용할 필드를 지정하고 중복이나 복원 오류를 검사합니다.
- **실행 관측**: 단계별 실행 시간, 대기 시간, 모델 호출, 토큰 사용량과 오류를 기록해 병목을 분석합니다.
- **추론 가속 실험**: 원래 모델이 제안 토큰을 검증하는 추측 디코딩 등 모델 서빙 기법을 동일 조건에서 비교합니다.
- **성능·품질 검증**: 같은 질문으로 기존 방식과 개선 방식을 반복 비교하고, 평균·95백분위 응답시간, 처리량, 오류 없는 완료율과 검색 근거 일치도를 평가합니다.

## 적용 방식

현재 검증 대상은 **검사된 직접 실행 어댑터**입니다. 모델·프롬프트·서빙 옵션을
바꾸지 않고 중복 도구 호출을 제거하되, 전체 응답 시간과 품질을 함께 평가합니다.
[2026-09-18 검증 계획](docs/DISPATCH_VALIDATION_PROTOCOL_20260918.md)에 수정 내용,
수용 기준 초안, 200문항 반복 설계와 실행 전 조건을 정리했습니다. 새 GPU 결과는
아직 없으며, 위의 다른 실험 기능은 이 비교에 함께 적용하지 않습니다.

공통 모듈은 특정 도메인이나 에이전트 프레임워크에 의존하지 않도록 구성합니다. 적용하는 시스템에서 작업 의존성, 모델 호출 함수, 참조 ID 필드와 품질 평가 기준을 연결합니다. 실제 적용 범위와 성능·품질은 각 시스템에서 검증해야 합니다.

## 저장소 구성

- `src/cnu_rag_optimization/`: 공통 어댑터, 실행·전송 관리 및 평가 모듈
- `examples/`: 어댑터 연동 예제
- `integrations/`: 개별 검색 시스템 연동 코드
- `scripts/`: 실험 실행, 계측 및 결과 분석 도구
- `tests/`: 기능 검증 테스트
- `docs/`: 설계와 실험 방법 문서
