# 400-query compiled-procedure ablation — 2026-09-03

## Scope

This case study tested application-side optimization only. Model weights,
inference-server settings, decoding settings, and invocation method were held
fixed. Original application source, prompts, credentials, endpoint addresses,
question text, and raw domain data are excluded from this repository.

The retrieval snapshot contained 3,673,482 indexed records. Evaluation used the
same 400 queries for every method: four difficulty groups with 100 queries each.
Concurrency was 4, with three warm-ups excluded. Each method ran once.

The control output was frozen as pseudo-gold. Fidelity combines ranked-document
agreement and response semantic similarity. It measures preservation of current
behavior, not expert-judged factual correctness.

## Methods

| Method | Operation |
|---|---|
| Control | Existing sequential multi-agent execution. |
| Contract link-state route | Select an equivalent path using recent delay, in-flight load, failure rate, and required contracts. |
| Compiled procedure reuse | Execute a trace-verified stage/action pair only when typed input contracts hold; otherwise use the existing agent. |
| Bounded overlap | Add one independent read-only task beside compiled procedure execution. |
| Short procedure guidance | Add at most two retrieved execution hints to the compiled procedure. |

Link cost was calculated as:

`EWMA delay × (1 + in-flight requests / capacity) + failure penalty`

No previous answer was cached or reused.

## Result

| Method | Mean | p50 | p95 | p99 | LLM calls/query | Pseudo-gold fidelity | Decision |
|---|---:|---:|---:|---:|---:|---:|---|
| Control | 44.08 s | 33.75 s | 124.82 s | 188.49 s | 10.16 | Reference | Control |
| Contract link-state route | 27.66 s | 24.90 s | 84.78 s | 137.76 s | 7.34 | 0.7450 | Rejected |
| Compiled procedure reuse | 27.50 s | 24.22 s | 58.08 s | 125.38 s | 9.07 | 0.9102 | Rejected |
| Bounded overlap | 29.60 s | 27.97 s | 54.27 s | 117.27 s | 9.13 | 0.9090 | Rejected |
| Short procedure guidance | 32.57 s | 28.29 s | 81.72 s | 148.83 s | 9.05 | 0.9064 | Rejected |

All methods completed 400/400 requests. Compiled procedure reuse had the
strongest paired latency result: mean per-query reduction 16.3%, bootstrap 95%
confidence interval 10.0%–22.1%, and 73.8% of paired queries faster. Its
document-ID Recall was 0.8750, nDCG@10 was 0.8596, Top-1 agreement was 0.7900,
and answer similarity was 0.9495.

## Interpretation

The latency effect is measurable, but none of these four variants passed this
repository's predefined 0.97 aggregate fidelity gate. They are ablations, not
accepted accuracy-preserving improvements. The accepted default remains the
safe hybrid reported in [APPLICATION_SIDE_EXPERIMENTS.md](APPLICATION_SIDE_EXPERIMENTS.md).

The one-pass methods were run in separate time windows, so changing external
load can confound raw aggregate means. A cyclic, block-interleaved replication
was started to control time-window load. It stopped before completion at 180,
180, 160, 180, and 180 successful queries across five methods; incomplete data
is excluded from conclusions.

Publication-grade follow-up requires completed interleaving, repeated queries,
and expert-labelled relevance judgments. Internal chain-of-thought was not
available and was not reconstructed; evaluation used observable stage timing,
tool calls, selected document IDs, and final responses.
