# 2026-09-16 실험 완료율 정정

## 무엇이 잘못 집계됐는가

기존 `pipeline_ok`는 응답 스트림 완료와 오류 문구 검사를 사용했다. 그러나 준비 단계의
120초 모델 호출 제한에 걸려도 앱이 오류를 친절한 안내문으로 다시 작성했고, 이 응답은
정상으로 집계됐다. 선택 단계에서도 실패한 모델 호출 뒤에 응답이 반환되는 경우가 있었다.
**응답 수신 완료와 내부 오류 없는 실행 완료는 같은 지표가 아니다.**

또한 이전 1~200 실험의 재정렬 HTTP 호출은 모두 401이었다. 앱은 예외를 잡아 기존
검색 순서로 결과를 반환했다. 따라서 당시 결과는 정상 재정렬을 사용한 검색기의 성능으로
해석할 수 없다. 인증 보정 효과는 새 실행 제어 방법의 효과와 분리해 측정한다.

새 열은 실패한 모델 호출이 하나라도 관측되면 제외하는 보수적인 지표다. 실패 뒤 복구한
응답도 제외하므로, 이를 정답률 또는 모든 제외 응답이 오답이라는 뜻으로 해석하지 않는다.
재정렬 401은 이 열과 별도인 **외부 기능 오류**로 기록한다. 재정렬을 호출하지 않은
경로도 있어 전체 요청 수와 재정렬 호출 수는 다르다.

200개 구간의 이전 완료율 차이만으로 정상 검색 성능이 개선됐다고 주장할 수 없다.
평균·p95 관측시간 원자료는 바꾸지 않았지만, 이 값에는 오류 안내문 반환 시간도 포함된다.

## 재현 가능한 판정 기준

1. 비공개 응답의 세션 ID로 앱 추적을 연결하고, 워크플로 추적 ID로 모델 호출 기록을 연결한다.
2. 기존 준비 실패는 `preparation` 모델 호출 실패와 실패 분기의 빈 출력 해시를 **둘 다** 확인한다.
3. 새 실행은 준비 실패를 문구 검사 대신 `dependency_failure` 이벤트로 직접 기록한다.
4. `stage_clean_completion`: 기존 완료 판정에 더해 준비 실패·모델 호출 실패·기록된 모델 오류가 없다.
5. `dependency_clean_completion`: 위 조건에 더해 관측된 guardrail·재정렬 호출이 모두 HTTP 200이고 외부 기능 오류가 없다.
6. 완료 응답의 추적이 없으면 성공으로 추정하지 않고 감사 오류로 처리한다. 이번 완료 응답에는 누락이 없다.

어느 지표도 전문가 답변 정확도 판정을 대신하지 않는다. 시간 초과 요청은 원래 실패로
유지하며, 결과를 받지 못해 세션 ID를 연결할 수 없는 경우에도 성공으로 전환하지 않는다.

## 검색 일치 지표의 명칭

기존 보고서의 “법령 재현율”은 반환 문서의 `item_id` 또는 `id`를 해시한 목록의
재현율이었다. 상위 법령 ID로 묶은 지표가 아니므로 **반환 근거 ID 재현율**로 명칭을
바로잡는다. 수치는 바뀌지 않는다. 상위 법령 ID를 기준으로 하는 원천 법령 포함률과도
구분한다. 어느 쪽도 전문가 정답 정확도는 아니다.
