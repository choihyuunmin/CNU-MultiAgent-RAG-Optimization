## 무엇을 실행했나

- 공개 패키지(커밋 5e5c990)로 번들을 새로 만들어 `try_typed_single_tool_dispatch`(validator 필수, 무손실 JSON 스냅샷, 실패 시 재시도 없음)를
  직접 실행 경로로 사용했다. 옛 ZIP은 쓰지 않았다(파일별 해시는 `review-inventory.json`).
- 서빙 스크립트는 공개 `ApplicationAdapter`(생성자에 `alias_to_resource` 없음)에 맞춰 수정했다. 이 어댑터는 호출별 `llm_finished` 대신
  `request_finished`의 호출 목록을 남기므로 분석기가 두 형식을 모두 읽도록 했다.
- 스모크 20문항 × 2 arm(40요청, 모두 정상) 뒤 200문항을 원본→직접 실행 순으로 1회, 원본 반복 1회(총 640요청, 실패 0). 동시성 4, 타임아웃 600초,
  엄격 유휴 게이트 통과(고착 요청 없음).

## 수용 판정

`evaluate_release_gate`: release_allowed = false. 사유: thresholds_not_predeclared, execution_equivalence_not_verified(인스턴스 간 출력 비동일),
missing_or_duplicate_loads, c4:insufficient_samples, c4:pairing_or_resampling_missing, c4:mean_latency_target_not_established,
c4:tail_latency_target_not_established, c4:quality_evidence_missing. 1단계 목적(연결·추적·실행 의미 점검)은 충족했고 성능 결론은 내리지 않는다.

## 2단계 전에 필요한 것

1. 검색 결과의 인스턴스 의존성 통제(인덱스 스냅샷 고정, 인스턴스 내부 캐시/재정렬 설정 확인) 또는 arm당 인스턴스 여러 개.
2. 새 200문항 holdout과 전문가 정답(방식명 가림). 3. 수용 기준 동결(주 부하 100, 5% 하한, p95 비 1.05, 품질 허용폭 0).
4. 4블록 Williams 설계(22,400요청)는 예산·시간 승인 후 실행.
