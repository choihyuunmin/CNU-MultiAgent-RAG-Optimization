# 다중 에이전트 법령 검색 시스템의 단계별 지연 최적화와 평가 지표 불일치에 관한 실증 연구

작성 기준: 2026-09-05 완료 실험. 아래는 실측 결과에 기반한 논문 본문 초안이다. 전문가 평가가 완료된 법률 정확도 연구가 아니라, 출처 기반 검색 평가와 백엔드 API 지연을 결합한 시스템 실증 연구로 범위를 한정한다.

## 초록

다중 에이전트 검색 시스템의 최적화에서는 모델 호출 지연뿐 아니라 질의 변환, 후보 검색, 재정렬, 답변 생성 사이의 상호작용을 함께 평가해야 한다. 본 연구는 법령 검색 시스템에서 동일 모델의 실행 경로 최적화, 인증이 복구된 재정렬, 답변 생성의 추론량 조정, 원 질문 보존 검색을 비교하였다. 400개 고유 질문을 구성하고 스트리밍 API 2,400회와 일반 JSON API 800회를 측정하였다. 검색 평가는 기존 시스템 출력과의 일치도 외에, 서로 다른 법령 240개에서 구성한 출처 라벨과 참조 문자열 검증을 통과한 조문 질문 131개를 사용하였다.

복합 최적화 조건은 스트리밍 API 평균 지연을 13.772초에서 10.619초로 22.89% 단축하였고, 평균 첫 답변 지연을 21.43% 단축하였다. 동일 후보 집합의 재정렬은 출처 조문 Hit@1을 0.8168에서 0.9008로 개선하였다. 별도의 준비·검색·재정렬 실험에서 원 질문을 유지하고 생성형 추출을 생략한 조건은 평균 8.03배 빨랐다. 특히 동일한 131문항에서 원 질문 조건은 작은 모델 추출보다 기존 문서 일치도가 낮았지만 출처 조문 Hit@1은 높았다. 이는 기존 출력에 대한 회귀 지표와 출처 기반 검색 지표가 최적화 후보를 상반되게 평가할 수 있음을 보여준다. 다만 최종 답변 품질의 개선이나 동등성은 입증하지 못했으며, 출처 라벨은 전문가 정답을 대체하지 않는다.

## 1. 연구 목적과 연구 질문

기존 실험에서는 오케스트레이터의 디코드 지연과 질의 추출 변화에 따른 검색 문서 불일치가 주요 문제로 관찰되었다. 그러나 분석·검색 단계의 지연만으로 최종 사용자 응답 시간을 설명할 수 없고, 기존 시스템이 반환한 문서를 정답으로 간주하면 기존 오류를 반복하는 최적화가 유리하게 평가될 수 있다. 따라서 본 연구는 속도, 출처 검색, 최종 답변 평가를 분리하여 다음을 검증하였다.

1. 모델을 교체하지 않고 호출 경로와 실행 순서를 바꾸면 백엔드 API 전체 지연을 줄일 수 있는가?
2. 재정렬 복구는 새로운 관련 법령의 발견과 이미 검색된 조문의 순위 중 어느 부분을 개선하는가?
3. 값싼 모델로 추출기를 대체하는 대신 원 질문을 검색에 사용하면 어떤 지연·출처 적중 특성이 나타나는가?
4. 기존 출력 일치도와 출처 기반 지표는 최적화 후보에 같은 우선순위를 부여하는가?
5. 네트워크, 생성 추론량, 국가 후처리, 안전 분류 등의 실패 요인을 단계별로 구분할 수 있는가?

주 종단 조건은 본 실행 전에 결정하였다. 국가 보정, 원 질문 검색 등의 추가 분석은 탐색적 분석으로 구분하며, 전체 연구가 외부에 사전 등록되었다고 주장하지 않는다.

## 2. 실험 방법

### 2.1 시스템과 실행 환경

시스템은 의도 분류, 검색 준비, 하이브리드 검색, 재정렬, 문서 선별 및 답변 생성으로 구성된다. 오케스트레이터는 gemma-4-31B-it, 주요 worker는 gpt-oss-20b, 임베딩은 BGE-M3, 리랭커는 bge-reranker-v2-m3-ko를 사용하였다. 최종 답변의 자동 심사에는 생성 worker와 다른 phi-4를 사용하였다.

GPU 추론은 gpu-host(.53)의 기존 H200 NVL 2개에서 수행하였다. app-host(.52)에는 GPU가 없음을 확인하여 서버 간 네트워크 측정에만 사용하였다. 운영 모델을 재시작하지 않고 고정한 앱 소스 복사본과 별도 loopback 앱 프로세스에서 실험하였다. 검색 대상은 번역 문서 453,965건과 원문 문서 3,197,052건, 합계 3,651,017건의 실제 공유 색인이었다.

종단 지연의 측정 범위는 .53의 클라이언트가 백엔드 API 요청을 시작한 시점부터 응답을 모두 받은 시점까지다. .52의 운영 Nginx, 실제 배포 앱의 CPU 배치, 브라우저 렌더링까지 포함한 서비스 SLA 시험은 아니다. GPU는 기존 서비스와 공유하였고 prefix cache를 초기화하지 않은 warm 조건이었다.

### 2.2 질문 집합과 출처 라벨

400개 질문을 중복 없이 구성하였다. 출처형 질문은 서로 다른 법령 240개 및 57개 국가·지역·기구에 걸쳐 표집하였다.

| 질문 유형 | 문항 수 |
|---|---:|
| 법령명 검색 | 80 |
| 출처 조문 주제 질문 | 63 |
| 출처 의미 재서술 질문 | 68 |
| 참조 문자열 검증 실패 후 법령·조문명 검색으로 대체 | 29 |
| 상황형 법령 검색 | 100 |
| 국가 비교 | 20 |
| 자기완결적 번역 | 20 |
| 대화·서비스 안내·범위 밖 | 20 |
| 합계 | 400 |

법령 수준 평가는 출처형 240문항에 적용하였다. 정확한 조문 수준 평가는 참조 답변이 출처 원문에 실제로 존재하는 연속 문자열인지 검증한 131문항에만 적용하였다. 법령명만 묻는 질문에 특정 조문을 임의의 유일 정답으로 지정하지 않았으며, 나머지 질문에도 정답 문서를 임의로 부여하지 않았다.

이 라벨은 출처가 알려진 문서를 다시 찾는 평가용 silver known-item 라벨이다. 모든 관련 문서를 열거한 relevance gold가 아니며, 다른 문서도 질문에 유효한 답을 제공할 수 있다. 질문의 법률적 타당성과 답변의 사실성에 대한 전문가 검토는 아직 수행하지 않았다. 별도의 예비 24문항은 본 실험과 출처 법령 ID가 겹치지 않으며 본 결과에 합산하지 않았다.

### 2.3 종단 비교 조건

| 조건 | 변경 사항 |
|---|---|
| baseline | 고정한 현재 앱의 순차 실행과 LiteLLM 프록시 경로. 리랭커 인증 실패 시 기존 fallback 유지 |
| speed | 동일 모델 직접 연결, typed dispatch, 입력 일치 확인을 거친 준비 단계 중첩, 진행 중 동일 임베딩 요청 합치기, 반복 검색 설정 호출 감소, 인위적 스트리밍 대기 제거 |
| balanced | speed에 본문 리랭커 인증 복구와 gpt-oss 스트리밍 답변의 낮은 추론량 설정 추가 |

모델·임베딩·가드레일 인증은 실행 가능한 공통 전제 조건으로 모든 조건에서 복구하였다. 따라서 이번 baseline은 이전 날짜의 실험 baseline과 동일하지 않다.

준비 단계 중첩은 적격한 신규 단일 법령 질의에 한해 분류 결과가 나오기 전에 준비를 시작하는 방식이다. 분류가 해당 검색 경로를 허용하고 실제 사용될 전체 대화 입력과 준비 입력이 정확히 일치할 때만 결과를 사용한다. 그렇지 않으면 정상 준비 경로를 실행하고 사용하지 않은 작업은 취소·회수한다. 임베딩 요청 합치기는 동시에 진행 중인 동일 입력에만 적용하며 완료된 답변을 캐시하는 방식이 아니다.

낮은 추론량 설정은 SSE 답변 생성에만 적용하였다. JSON 경로에는 적용하지 않았다. 또한 정상 재정렬은 Top-20을 반환하지만 기존 401 fallback은 후보 전체를 반환할 수 있으므로 balanced의 종단 효과에는 생성 문맥 구성 차이도 포함된다. 이를 인증만 또는 추론량만 바꾼 독립 대조 실험으로 해석하지 않는다.

### 2.4 반복, 측정 지표 및 통계

SSE는 400문항 × 3조건 × 2회로 2,400회, JSON은 400문항 × 2조건 × 1회로 800회 측정하였다. SSE 동시성은 4였으며 8문항 블록별로 조건 순서를 회전·반전하였다. 조건 간 요청은 겹치지 않게 하고 매 요청에 새 세션을 사용하였다. 조건별 2개의 warmup 요청은 제외하였다.

전체 지연은 요청 시작부터 응답 종료까지로, TTFT는 progress 이벤트가 아니라 처음 표시 가능한 답변이 도착할 때까지로 정의하였다. 평균과 p50·p95·p99·최댓값을 산출하고 타임아웃과 긴 꼬리를 제거하지 않았다.

검색 평가는 재정렬 직후의 출처 조문 Hit@1/5/20과 MRR@20을 사용하였다. 최종 API는 반환 법령을 item_id로 다시 정렬하므로 반환 목록의 첫 항목을 검색 Top-1으로 평가하지 않았다. 종단에서는 반환 근거에 출처 법령·조문이 포함되는지를 측정하였다. 기존 문서 일치도는 baseline 문서 집합을 기준으로 한 문서 ID Recall로 별도 보고하고, 빈 참조 집합은 해당 지표에서 제외하였다.

반복값은 질문별로 평균을 낸 후 질문 단위의 짝지은 bootstrap 4,000회로 95% 신뢰구간을 구하였다. 배속은 평균 지연의 비율로 계산하였다. Hit@1의 McNemar 정확 검정은 첫 반복의 질문별 쌍을 사용하고 세 재정렬 후보 비교에는 Holm 보정을 적용하였다. 반복을 독립 질문으로 계산하지 않았다. 사전 비열등성 한계를 설정하지 않았으므로 유의한 차이가 없다는 사실을 품질 동등성으로 해석하지 않았다.

## 3. 측정 결과

### 3.1 백엔드 API 전체 지연

조건별 800회의 SSE 결과는 다음과 같다. 단위는 초다.

| 조건 | 평균 | p50 | p95 | p99 | 최대 | 평균 TTFT |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 13.772 | 11.632 | 30.852 | 45.396 | 242.348 | 12.646 |
| speed | 12.213 | 10.237 | 27.603 | 39.341 | 241.555 | 11.469 |
| balanced | 10.619 | 9.013 | 23.681 | 35.420 | 82.611 | 9.935 |

speed의 평균 배속은 1.128배이고 지연 단축률은 11.32%였다(95% CI 5.20–16.70%). balanced는 1.297배, 평균 지연 22.89% 단축을 보였다(CI 19.54–26.92%). balanced의 평균 TTFT는 21.43% 단축되었다(CI 17.50–25.92%). p95와 p99의 개선은 점 추정치이며 이 백분위수 자체의 신뢰구간을 산출한 결과는 아니다.

JSON은 baseline 평균 13.000초에서 balanced 11.733초로 감소하였다. 배속은 1.108배, 단축률은 9.74%였다(CI 4.12–15.57%). SSE와 JSON은 구현 및 적용 최적화가 다르므로 SSE의 22.89%를 JSON에 일반화하지 않는다.

SSE의 HTTP 완료는 세 조건 각각 800/800회였으나 고정 타임아웃 안내 응답은 baseline 1회, speed 1회, balanced 0회였다. 두 타임아웃을 통계에서 제외하지 않았다. 내부 모델 예외도 별도로 관측되었으므로 HTTP 성공을 정상적인 답변 성공과 동일시하지 않는다. 0회 대 1회만으로 타임아웃 확률의 유의한 개선을 주장할 수 없다.

### 3.2 종단 반환 근거와 답변 품질

| 조건 | 출처 법령 포함: 240문항 × 2회 | 출처 조문 포함: 131문항 × 2회 | baseline 문서 ID Recall |
|---|---:|---:|---:|
| baseline | 466/480 (97.08%) | 240/262 (91.60%) | 기준 |
| speed | 465/480 (96.88%) | 238/262 (90.84%) | 0.9772 |
| balanced | 467/480 (97.29%) | 240/262 (91.60%) | 0.9292 |

balanced의 법령 포함률 변화는 +0.208%p(CI −0.625–+1.250%p), 조문 포함률 변화는 0%p(CI −1.145–+1.145%p)였다. 최종 반환 근거의 유의한 개선이나 동등성은 입증하지 못하였다. speed의 조문 포함률도 0.763%p 낮아졌으므로 동일 모델을 사용했다는 이유만으로 무손실이라고 부르지 않는다.

131문항의 첫 SSE 답변을 조건명을 숨긴 phi-4로 평가한 393건은 모두 유효한 점수를 반환하였다. 질문 관련성과 근거 충실성은 각각 0–2점 척도다.

| 조건 | 관련성 평균 | 근거 충실성 평균 | 근거 불충분 판정 |
|---|---:|---:|---:|
| baseline | 1.9084 | 1.9084 | 6/131 |
| speed | 1.9084 | 1.9008 | 5/131 |
| balanced | 1.9008 | 1.9008 | 6/131 |

balanced의 두 점수 변화는 각각 −0.00763(CI −0.05344–+0.03053)이었다. 자동 심사 결과에서도 최종 답변 품질의 개선 또는 동등성은 입증하지 못하였다. 심사 입력은 참조 출처와 최종 반환 근거의 처음 10개로 제한되며 생성기가 읽은 모든 문맥은 아니다. 점수를 전문가 정답률로 환산하지 않는다.

### 3.3 동일 후보 집합의 재정렬

첫 대형 모델 추출을 고정하고 400문항을 세 번 새로 검색하였다. 각 검색의 동일 후보를 네 재정렬 방식으로 비교하였다. 조문 지표는 131문항에 해당하며 검색 시간은 400문항 기준으로 추출 시간을 제외한다.

| 재정렬 조건 | Hit@1 | Hit@5 | MRR@20 | 검색+재정렬 평균 |
|---|---:|---:|---:|---:|
| 재정렬 없는 raw | 0.8168 | 0.9695 | 0.8817 | 0.337초 |
| 인증 정상·본문 입력 | 0.9008 | 0.9618 | 0.9245 | 0.438초 |
| 국가·제목·조문 메타데이터 입력 | 0.9084 | 0.9695 | 0.9307 | 0.443초 |
| 질의 관련 본문 구간 입력 | 0.9084 | 0.9695 | 0.9307 | 0.441초 |

본문 리랭커는 출처 조문 Hit@1을 107/131에서 118/131로 8.40%p 개선하였다. 질문별 개선은 15개, 악화는 4개였으며 McNemar p=0.01921, Holm 보정 p=0.03545였다. MRR 증가량 0.04283의 CI는 0.00614–0.08079였다. 검색·재정렬 평균 비용은 약 0.101초 증가하였다.

오류 분해에서는 raw의 Top-1이 출처 조문 107개, 같은 법령의 다른 조문 19개, 다른 법령 5개였고, 본문 리랭커 적용 후 각각 118개, 8개, 5개였다. 개선과 악화는 모두 같은 법령 내부의 조문 순서 변화였다. 따라서 결과는 법령 자체의 추가 발견보다 조문 선택 정밀도의 개선을 뒷받침한다. Hit@20은 모든 조건에서 0.9695였고 본문 조건의 Hit@5는 한 문항 낮았으므로 모든 순위 절단점의 개선은 아니다.

메타데이터와 관련 구간 입력은 본문 입력보다 Top-1이 한 문항 높았으나 추가 효과의 유의성을 입증하지 못하였다. 별도 400문항 잘림 처리 대조군에서는 원 helper와 실험 본문 입력의 출처 지표가 같았지만 전체 Top-20 순서의 완전 일치는 80%였다. 이를 순위 전체의 동일성 증거로 사용하지 않는다.

### 3.4 원 질문 보존과 작은 추출기 비교

400문항을 네 조건에서 한 번씩 실행한 검색 전용 실험 1,600회가 모두 완료되었다. 모든 조건에서 인증이 정상인 본문 리랭커를 사용하였다. 시간은 준비·검색·재정렬을 포함하되 의도 분류, 가드레일, 문서 선별, 대화 처리, 답변 생성은 포함하지 않는다.

| 검색 전용 조건 | 평균 시간: 400문항 | 조문 Hit@1: 131문항 | 조문 Hit@20 | 조문 MRR@20 | 법령 후보 포함: 240문항 |
|---|---:|---:|---:|---:|---:|
| 기존 대형 모델 전체 준비 프롬프트 | 3.425초 | 118/131 (0.9008) | 127/131 | 0.9245 | 232/240 |
| 원 질문·유일한 명시 국가·키워드 없음 | 0.426초 | 120/131 (0.9160) | 130/131 | 0.9454 | 239/240 |
| 원 질문과 기존 추출의 후보 합집합 후 재정렬 | 3.470초 | 120/131 (0.9160) | 131/131 | 0.9464 | 240/240 |
| 같은 전체 준비 프롬프트의 작은 모델 추출 | 2.631초 | 110/131 (0.8397) | 127/131 | 0.8842 | 231/240 |

원 질문 조건은 8.034배 빨랐고 평균 지연은 87.55% 감소하였다(CI 86.66–88.34%). 기존 준비 조건 대비 Top-1은 개선 7문항, 악화 5문항으로 McNemar p=0.7744였으며 MRR 변화 +0.02091의 CI는 −0.01798–+0.06272였다. 따라서 관측된 검색 단계 가속은 확인했지만 품질의 유의한 개선이나 동등성을 입증하지는 않았다.

작은 모델 추출은 1.302배 빨랐으나 Top-1이 6.11%p 낮았다. MRR 변화는 −0.04027(CI −0.07281–−0.01136)이었다. Top-1의 원 p값은 0.02148이지만 Holm 보정 후 0.06445이므로 보정된 Top-1 검정의 유의성을 주장하지 않는다. 관측된 출처 손실 때문에 정확도 우선 대안으로 선정하지 않았다.

후보 합집합은 원 질문과 기존 준비 검색을 병렬 실행하고 중복을 제거한 뒤 전체 합집합을 재정렬하였다. 지정된 법령 240개가 모두 후보에, 지정된 조문 131개가 모두 Top-20에 포함되었다. 다만 평균 시간은 기존 준비보다 44.57ms 증가하였다(CI 37.35–51.52ms). 이 결과는 서로 다른 검색 표현의 후보 보완성을 보여주지만 모든 관련 문서의 Recall 100% 또는 법률적 정확도 100%를 의미하지 않는다. 전체 합집합을 다시 재정렬하므로 효과를 RRF 순위 공식만의 독립 효과로 돌리지 않는다.

### 3.5 기존 출력 일치도와 출처 지표의 후보 순위 역전

평가 모집단 차이로 인한 착시를 피하기 위해 동일한 출처 조문 질문 131개에서 두 지표를 비교하였다.

| 후보 | 기존 준비 결과 대비 문서 ID Recall | 출처 조문 Hit@1 |
|---|---:|---:|
| 원 질문 검색 | 0.5116 | 0.9160 |
| 작은 모델 추출 | 0.6934 | 0.8397 |

기존 문서와의 일치도만 보면 작은 모델 추출이 우세하지만, 알려진 출처 조문을 첫 순위에 반환하는 비율은 원 질문 조건이 높다. 이는 같은 평가 집합에서도 지표 선택에 따라 후보 우선순위가 뒤집힐 수 있음을 보여주는 실측 반례다. 따라서 기존 출력 일치도는 회귀 감시 지표로 사용할 수 있으나 관련 출처 검색이나 답변 정확도의 대리 정답으로 단독 사용해서는 안 된다.

이는 이번 데이터의 관측 결과이지, 과거 다른 질문 집합에서 나타난 작은 모델의 실패를 소급하여 무효화하는 증거가 아니다. 또한 원 질문 조건의 전문가 정확도 우월성이나 기존 조건 대비 품질 동등성을 의미하지 않는다.

### 3.6 생성·네트워크·후처리 분리 실험

고정 생성 입력 60문항을 세 조건에서 두 번씩 실행한 360회 대조군에서는 다음을 관측하였다.

| 생성 호출 조건 | 평균 시간 | 평균 모델 TTFT |
|---|---:|---:|
| 프록시·기본 추론 | 2.804초 | 1.936초 |
| 직접 연결·기본 추론 | 1.996초 | 1.298초 |
| 직접 연결·낮은 추론 | 1.161초 | 0.247초 |

직접 연결 기본 대비 낮은 추론은 평균 41.84% 빨랐다(CI 23.95–53.17%). 표시 답변 평균 길이는 감소하지 않았고 추론 문자 수가 줄었다. 그러나 출력은 동일하지 않았고 이 대조군의 전문가 답변 평가는 없으므로 무손실 생성 가속이 아니다. 프록시와 직접 연결 사이에서도 추론·답변 길이가 달라져 0.808초 차이를 순수 네트워크 비용으로 해석할 수 없다.

서버 간 health 요청은 새 연결 1.699ms, 연결 재사용 1.042ms였다. LLM 추론을 제외한 연결 재사용 효과는 밀리초 수준이므로 전체 수초 단축의 주원인으로 설명할 수 없다. 실제 스트리밍 delta를 재생한 CPU 실험 340문항에서는 인위적 전송 대기 제거로 평균 95.44ms가 줄었고 문자와 순서는 340/340문항에서 같았다. 이 동일성은 해당 전송 helper 재생에만 적용되며 전체 생성 결과나 브라우저 표시의 무손실성을 뜻하지 않는다.

국가 후처리 감사에서는 동일 서빙의 국가 반복 일치율이 100%인데도 출처 국가가 다른 질문 7개를 발견하였다. 긴 관할명 뒤에 붙은 한글 조사 때문에 짧은 상위 국가가 선택되는 최소 차이 사례를 재현하였다. 국가만 보정한 새 검색 대조군에서는 출처 법령 후보 포함이 232/240에서 238/240으로, 조문 Hit@1이 118/131에서 120/131로 증가하였다. 후자의 McNemar p=0.5이므로 일반적 개선으로 확대하지 않는다. 원 종단 경로에서는 복수 하위 검색을 통해 국가 불일치 7문항 모두 이미 출처 법령을 반환했으므로 이 개선량을 종단 효과로 대입하지 않는다.

또한 자동 답변 평가의 공통 저득점 5문항은 검색 순위와 무관한 개인정보 경고 경로에 진입하였다. 사후 동일 입력 재생에서 5개 모두 `<UNSAFE-S4>`가 반환되고 앱에서 `pii`로 매핑됨을 확인하였다. 이는 검색 전 단계의 코드·안내 범주를 함께 감사해야 함을 보여주는 오류 진단이며, 전체 안전 분류 정확도 평가나 차단 완화의 근거가 아니다. 원 실험의 원시 분류 토큰은 저장하지 않았으므로 최초 요청을 소급 복원한 결과로 기술하지 않는다.

## 4. 비교 분석과 논의

첫째, 단계별 배속과 종단 배속을 구분해야 한다. 원 질문 검색의 8.03배는 생성형 준비를 생략한 검색 전용 결과이고, 사용자가 답변을 모두 받을 때까지의 스트리밍 API 배속은 1.297배였다. 과거 n-gram 분석 단계의 1.89배 역시 이번 전체 API 결과와 직접 비교하거나 곱할 수 없다. 이번 연구에서 n-gram은 CPU 호환성·제안기 참조 검사를 수행했을 뿐 GPU 종단 가속을 재측정하지 않았다.

둘째, 정확도 변화는 후보 발견, 후보 순위, 최종 근거 포함, 답변 품질로 나누어야 한다. 재정렬의 +8.40%p는 동일 법령 내부의 출처 조문 순위 개선이었다. 반면 국가 필터 오류는 출처가 후보에 들어오는지에 영향을 주었다. 최종 근거 포함과 자동 답변 점수는 별도의 단계이며 검색 Top-1 개선만으로 최종 답변 정확도 개선을 결론 내릴 수 없다.

셋째, 값싼 추출기와 추출 생략은 다른 설계 선택이다. 작은 모델로 전체 준비 프롬프트를 실행하면 질의 표현 변화에 따른 출처 손실과 생성 비용이 함께 남을 수 있다. 이번 명시적 국가·법령 질문 집합에서는 원 질문 검색이 더 빠르고 높은 출처 적중 점 추정치를 보였다. 그러나 원 질문 조건은 국가 선택과 키워드 생략도 함께 바꾸었고, 국가-only 대조군 역시 Top-1이 120/131이었다. 원 질문 보존만의 독립적인 정확도 효과를 주장할 수는 없다.

넷째, 출력 안정성과 정확성은 다르다. 같은 baseline의 반복 문서 ID Recall도 0.9882였고 준비 필드 완전 일치율은 397/400이었다. 반대로 국가 후처리 오류는 매번 동일하게 반복되었다. 반복 대조군은 자연 변동을 측정하지만 정확성을 보장하지 않으며, 출처 라벨은 기존 시스템의 일관된 오류를 발견하는 보완 수단이다.

## 5. 연구의 기여

### 기여 1: 회귀 일치도와 출처 검색 성능의 불일치를 실측으로 제시

동일한 131문항에서 문서 ID Recall은 작은 추출기를, 출처 조문 Hit@1은 원 질문 검색을 우선하는 후보 순위 역전을 확인하였다. 새로운 정확도 지표를 발명했다기보다, 기존 출력만을 정답으로 사용하는 최적화 평가의 한계를 실제 법령 검색 시스템에서 구체적으로 드러낸 경험적 기여다.

### 기여 2: 입력 일치 검증을 포함한 실행 최적화와 백엔드 종단 검증

준비 단계 선실행 결과의 사용 조건을 의도 경로와 전체 입력 일치로 제한하고, typed dispatch·동시 임베딩 요청 합치기·전송 대기 제거 등을 통합하였다. 동일 모델 실행 경로 조건에서 SSE 평균 지연 11.32%, 복합 조건에서 22.89% 단축을 측정하였다. 개별 기법 각각의 독립 기여나 출력 동일성을 입증한 연구로 표현하지 않는다.

### 기여 3: 원 질문 보존과 후보 보완의 비교 근거 제공

대형 추출기, 작은 추출기, 원 질문, 두 경로 후보 합집합을 같은 질문 집합과 정상 리랭커에서 비교하였다. 원 질문 조건의 검색 단계 8.03배 가속과 후보 합집합의 알려진 출처 보완성을 관찰하였다. RRF나 질의 결합 자체의 알고리즘 신규성 대신, 해당 시스템에서의 비교 결과와 적용 조건을 기여로 제시한다.

### 기여 4: 오류 전파와 긴 꼬리의 단계별 분해

리랭커 인증 fallback, 동일 법령 내 조문 순위, 국가 후처리의 후보 누락, 검색 전 안전 분류 경로, 첫 답변 전 추론과 첫 답변 후 장문 생성 지연을 구분하였다. 이를 통해 단순히 LLM 호출 전체를 병목으로 묶는 분석보다 구체적인 개선·검증 대상을 제시하였다. 인증 수정 자체를 새로운 검색 알고리즘으로 주장하지 않는다.

### 기여 5: 다층 측정과 재현 가능한 실험 산출물

400개 고유 질문, 3,200회의 API 요청, 동일 서빙 반복, 동일 후보 재정렬, 고정 생성 입력 및 조건명을 숨긴 자동 심사를 연결하였다. 주·추가 워크로드 8,353행의 질문·조건·반복 조합과 해시를 감사하여 중복·누락이 없음을 확인하였다. 이 행 수는 GPU 추론 호출 수가 아니며, 산출물 완결성은 답변 정확성을 보증하지 않는다.

## 6. 한계와 후속 검증

가장 큰 한계는 전문가 gold의 부재다. 출처 문자열 검사와 단일 LLM 심사는 법률적 사실성, 유용성, 질문의 타당성을 검증하지 못한다. 후속 연구에서는 서로 독립적인 전문가가 질문의 답변 가능성과 관련 법령을 판정하고, 조건명을 숨긴 최종 답변을 검토해야 한다. 이미 준비한 검토 패킷의 전문가 라벨은 현재 모두 미작성 상태다.

질문은 합성이고 국가·법령이 명시된 경우가 많다. 실제 로그의 빈도, 생략된 관할, 별칭, 다중 턴 문맥에 대한 대표성을 확보하지 못하였다. 일부 출처 질문 생성에는 답변 worker와 같은 모델 계열을 사용했으므로 표현 편향도 남아 있다.

공유 GPU 부하와 warm cache는 완전히 통제하지 않았으며 반복 수는 SSE 2회, JSON과 원 질문 비교 1회로 제한적이다. 질문 단위 신뢰구간이 모든 시간대의 경합 변동을 포괄하지 않는다. GPU 포화 처리량, 에너지, GPU-second 비용도 측정하지 않았다. 준비 선실행은 지연을 줄이는 대신 소비되지 않는 작업을 만들 수 있다.

balanced는 여러 변경을 묶은 조건이다. 독립 효과를 밝히려면 리랭커 정상화와 후보 수를 모든 비교군에서 맞추고, 직접 연결·준비 중첩·낮은 추론량을 요인별로 나눈 후속 대조가 필요하다. 품질 보존 주장을 위해서는 사전 비열등성 한계와 충분한 표본 수를 정해야 한다.

운영 소스와 모델은 고정했지만 색인은 immutable snapshot이 아니라 공유 색인이었다. 관측한 조기·최종 색인 상태는 같았으나 조기 점검이 주 측정 시작 이후였으므로 전 기간 불변성을 보증하지 않는다. 운영 배포, UI 회귀, 실제 .52 경로의 SLA도 검증하지 않았다. TP·MTP·EAGLE 및 n-gram의 GPU 파라미터 탐색은 이번 실측 결과에 포함하지 않는다.

## 7. 결론

본 연구는 다중 에이전트 법령 검색에서 동일 모델의 실행 경로 최적화와 단계별 평가를 통해 백엔드 응답 지연을 줄일 수 있음을 확인하였다. 복합 조건은 SSE 평균 지연을 22.89% 단축했고, 동일 후보의 재정렬은 출처 조문 Hit@1을 8.40%p 개선하였다. 별도의 원 질문 검색은 준비·검색·재정렬 구간에서 8.03배 빨랐다.

핵심적인 방법론적 결과는 기존 출력과의 일치도가 출처 기반 검색 성능과 다른 후보 순위를 만들 수 있다는 점이다. 따라서 속도 최적화는 기존 출력 회귀, 출처 검색, 최종 답변 품질을 분리하여 평가해야 한다. 현재 결과는 지연 감소와 일부 출처 순위 개선을 뒷받침하지만, 전문가 수준의 답변 정확도 개선이나 무손실성을 입증하지는 않는다.
