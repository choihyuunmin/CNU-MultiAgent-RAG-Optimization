## 완료와 실패

36개 trial은 모두300문항이며 질문·조건·반복·인덱스의 누락/중복을 검사했다.
응답 스트림 정상완료10,786건, 비정상14건을 지연 통계에 그대로 포함했다.
내부 오류가 기록된 요청11건은 스트림 완료와 다른 지표이므로 별도로 공개한다.
비공개 원문은 서버에 보존하고 공개 요청 파일에는 수치와 해시만 남겼다.

참조 답변이 있는98문항을 첫 재개 반복의6개 부하/3조건에서 자동 평가했다.
1,764개 평가 기록 중1,762개는 유효하고, U1 고정16의2개는 ReadError다.
판정 오류는0점이나 정상 판정으로 바꾸지 않았다. 판정 평균은 유효 집합에서 계산되며
U1 고정16의 분모는96, 다른 조건은98이다. 실패/빈 응답과 판정기 오류를 구분한다.

## 사용자 규모별 지연

A는 원래4/4상한·전송, B는16/16상한·즉시 전송, C는B에 고정 호출/토큰 예산을 더했다.
아래 평균은 완료 또는 실패 기한까지의 **관측시간**이며 성공 응답만의 평균이 아니다.
같은300문항의2회 반복을 질문별로 묶어 비교했다. C 대 B 단축률은 음수일수록 느리다.
95% 구간은 질문 단위 bootstrap이며 전체 캠페인 반복의 불확실성을 충분히 추정하지 못한다.

주 비교에서 정적 예산 C의 추가 가속은 확인되지 않았으며, U32에서는B보다 느렸다.
B와C가A보다 빠른 고부하 결과를 C만의 기여로 보고해서는 안 된다.
U1의A가U2보다 느린 비단조성도 있으므로 하나의 단조 확장 곡선으로 강제 해석하지 않는다.
초기 cache와 시간·실행 순서 효과가 포함될 수 있다. 기존 연구 결과의 개선율과 합산하지 않는다.

## 메모리·대기 관측과 해석 범위

trial 구간에서 host 가용 RAM 최저는463.33GiB이며 OOM kill·swap in/out 증가가 없었다.
이 관측은 host RAM 고갈 가설을 지지하지 않는다.
U32의 오케스트레이터 KV 관측 최대는 B92.62%→C63.12%로 줄었지만,
종단 평균은53.19→60.19초로 늘었다. 양쪽 오케스트레이터 선점 관측은0이었다.
KV 사용량 감소 자체가 응답 속도 개선을 보장하지 않는다는 반례다.

같은 U32에서 첫 이벤트 이전 평균은 B25.73초→C28.97초,
워커 인스턴스의 평균 queue 관측은0.51초→1.55초였다.
단계별 대기·동시성 제한·워커 작업량을 함께 살펴야 하며, 이것만으로 C의 지연 증가
전체를 특정 원인에 인과적으로 귀속할 수는 없다. 모델 지표는 공유 인스턴스 전체의
관측이며 외부 트래픽을 완전히 분리하지 않았다. GPU 메모리 활동률은 HBM GB/s가 아니다.
순수 CoT 계산 시간, HBM 대역폭 포화 또는 GPU 용량 부족을 확정하지 않는다.

## 정확도와 후속 판단

자동 support 평균(0~2)은 대부분 조건에서1.84~1.87 범위지만 이것을 전문가 정확도
비열등성으로 주장하지 않는다. U1 baseline은1.68이며 다른 부하/조건과 달리 저하가
관측됐으므로 결과를 숨기지 않는다. U1 B의 판정 오류2건에 따른 유효 집합 차이도 남는다.
기존 자동 평가의 짝지은 비교는A 기준이며 C 대 B의 별도 답변 비열등성 검정은 아니다.

현재 C는 기본 가속 정책으로 승격하지 않는다. 관측 어댑터와 대기/토큰 계측은 유지하고,
후속 정책은 **KV 압력 감소와 사용자 지연의 동시 평가**, 고정 call cap과 token budget의
효과 분리, 별도 데이터와 전문가 품질 검증이 필요하다. 이 커밋은 실측 결과의 보존이며
어댑터 예산 재튜닝이나 운영 배포를 수행하지 않는다.

복구 전후 검색 문서 수와 일부 모델 실행 명령이 달라졌다. 재개분도 독립 holdout이 아닌
회귀 데이터이고 반복은2회뿐이다. 운영 release는 계속 미승인이다.
