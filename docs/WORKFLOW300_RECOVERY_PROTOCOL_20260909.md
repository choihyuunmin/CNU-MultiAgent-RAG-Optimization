# 서버 재부팅 후 300문항 재개 계획

2026-09-09 사용자 요청에 따라 재개분을 조건별 400→300문항으로 줄인다.
서버 재부팅으로 중단된 원자료는 덮어쓰거나 성공 자료로 보정하지 않는다.

## 기존 실험과 재개분의 경계

기존 400문항 첫 반복은 6개 부하 × A/B/C = 18조건 전체가 완료됐다.
두 번째 반복 U1의 A/B는 각각400문항을 완료했고 C 도중 서버가 재부팅됐다.
이 A/B 결과와 C의 부분 결과도 별도의 중단 기록으로 보존한다.
재개 시에는 이 비교 묶음의 **세 조건 모두** 같은300문항으로 다시 측정한다.
성능이 나쁜 질문만 재시도하거나, 먼저 끝난300개 응답을 선택하지 않는다.

새 디렉터리에서 300문항 × 3조건 × 사용자1/2/4/8/16/32 × 남은2반복 =
**10,800요청, 36조건**을 실행한다. 반복 인덱스1/2와 seed20260909+인덱스를
유지하고 기존 순서 회전 규칙을 사용한다. 첫 재개 부하는 U1, 순서는 A/B/C다.
300개 질문은 기존400에서 종류별 비례 층화·고정 seed20260909로 선택하고,
지연·정답·실패 여부를 선택에 사용하지 않는다. 모든 부하와 조건에서 동일 집합을 쓴다.

이는 원래의400문항3반복 완료가 아니다. 복구 전400문항 자료와 복구 후300문항
자료를 단순 합산하지 않으며, 재개분의 주 비교는 동일 시기의 C 대 B다.
두 번뿐인 재개 반복에서는 세 조건의 시작 위치가 완전히 균형화되지 않는다.
공유 cache의 재부팅 초기화, 외부 트래픽, 시기 효과가 남는다.
복구 후 검색 문서 수와 모델 실행 명령 해시 차이도 기록한다.

## 유지되는 실험 설정과 평가

앱 소스·요청 primitive·어댑터 동작·A/B/C 설정은 기존 고정본을 유지한다.
정적 예산8/46,232/50,328과 출력 예약512를 재조정하지 않는다.
생성 출력 제한, 프롬프트, 운영 모델과 Kubernetes 설정은 변경하지 않는다.
데이터 접근은 기존 유효 설정으로 사전 점검하고 현재 운영 데이터에서 측정한다.

기존240초 기한, 개별 실패 보존, 요청별 내부 fallback trace 대조,
모델/검색/DB health 및 OOM/RAM/disk/GPU 감시,72시간 서비스 제한을 유지한다.
자동 재부팅·자동 재시작은 하지 않는다. SSH와 독립적인 실험 전용 서비스로 실행한다.

지연 측정 후 새300문항 중 참조 답변이 있는 질문을 첫 재개 반복(인덱스1)에서
6개 부하 × A/B/C로 자동 평가한다. 정확한 평가 레코드 수는 동결 manifest에 기록한다.
실패/빈 답변을 제외하지 않는다. 전문가 판정이나 비열등성 입증으로 부르지 않는다.
독립 holdout이 아닌 회귀 실험이며 운영 release는 여전히 허용하지 않는다.

실험 코드·상태·결과 공개 시 원시 질문/답변/trace와 인증 파일을 제외한다.
채팅에 노출된 Git 토큰을 저장·재사용하거나 자동 게시에 넣지 않는다.

## 재개 준비 단계의 평가 코드 수정

첫300문항 시작 직후, 기존 자동 judge가 반복0만 선택하는 문제를 발견했다.
실험 전용 STOP으로 해당 실행을 종료하고 원자료를 보존했다. 지연 설정을 수정한 것이
아니며 일부 응답 결과에 따른 질문/예산 재조정도 아니다. 해당 짧은 실행은 완성된
300문항 trial이 아니므로 본 비교에 합산하지 않는다.
judge에도 반복 번호를 명시적으로 전달하고, 빈 평가 집합·누락·중복을 오류로 처리하는
검사와 준비 단계부터 judge 선택까지의 회귀 테스트를 추가한 뒤 새 디렉터리에 동결한다.
