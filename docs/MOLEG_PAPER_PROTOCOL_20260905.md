# 400문항 후속 실험 프로토콜 (2026-09-05)

독립 예비셋 24문항으로 구현 동작과 재정렬 입력을 결정했으며, 본 실험은 별도의
400문항으로 수행한다. 본 종단 조건은 본 종단 실행 전에 결정했다. 이 문서는
외부에 사전 등록한 프로토콜이 아니며, 실행 중 계측 검증과 집계 오류 수정,
보수적인 다중비교 보정 설명을 추가했다. 실제 로그 분포나 법률 전문가 평가를
확보했다고 주장하지 않는다.

## 연구 질문과 조건

1. 동일 모델의 요청 경로 단축, 입력 일치 검증을 거친 준비 단계 선실행,
   중복 임베딩 합치기, 스트리밍의 인위적 대기 제거가 전체 응답 시간을 줄이는가?
2. 리랭커 인증 복구가 출처 문서의 순위를 개선하는가? 기존 입력, 국가·제목·조문
   입력, 질의 단어를 포함하는 본문 구간 입력을 동일 후보 집합에서 비교한다.
3. 검색어 추출에는 큰 모델을 유지하면서 최종 답변의 추론량만 낮추면
   지연과 답변 품질의 관계가 어떻게 달라지는가?

| 조건 | 분석·검색 | 답변 | 리랭커 |
|---|---|---|---|
| baseline | 고정한 현재 소스, 순차 실행, LiteLLM | 현재 설정 | 현재 인증 누락 |
| speed | 동일 모델 직접 경로, 검증된 준비 단계 중첩, typed dispatch, in-flight 임베딩 합치기, 설정 초기화 1회 | 현재 추론 설정, 인위적 전송 대기 제거 | baseline과 같음 |
| balanced | speed와 같음 | gpt-oss 스트리밍 답변에만 reasoning_effort=low | 인증 복구, 기존 본문 입력 |

모든 조건에서 모델·임베딩·가드레일 접속 인증은 실제 서빙 설정을 읽어 사용한다.
현재 소스의 가드레일에도 인증 헤더 누락이 있어 공통 선행 조건으로 복구한다.
따라서 baseline은 이전 날짜의 결과나 인증 실패 상태의 전체 운영 서비스와
동일한 수치가 아니라, 이번에 고정한 실행 가능한 비교 조건이다.
배포 소스·모델 서버는 재시작하지 않는다. 별도 앱 프로세스와 복사본만 사용한다.

`speed`는 의미적 계약을 유지하도록 설계했지만 bitwise 결과 보존을 가정하지
않는다. 병렬 스케줄, 라우팅 프록시와 모델의 수치 변동이 결과를 바꿀 수 있다.
`balanced`의 낮은 추론량은 명시적인 품질 절충 후보다. 정답 개선을 가정하지 않는다.

재정렬 어댑터의 본문형 입력은 본문 접두부를 설정된 문자 수까지 사용한다.
원 코드의 잘린 문자열 끝에 붙는 `…`는 붙이지 않는다. 따라서 이는 원 HTTP
요청의 인증 헤더만 byte-for-byte 바꾼 대조군은 아니다. 성공한 재정렬은 설정된
Top-20을 반환하지만, 기존 401 fallback은 후보 전체를 반환할 수 있다. 종단
balanced 결과에는 이런 후보 수·문맥 구성 차이도 포함되며, 낮은 추론량만의
효과로 전부 돌리지 않는다.

## 질문과 정답의 범위

400개 고유 질문: 색인의 서로 다른 법령 240개에서 만든 검색 질문 240개,
상황 검색 100개, 국가 비교 20개, 자기완결적 번역 20개, 대화·서비스 안내·범위 밖
질문 20개. 색인 문서는 국가별 순환 방식으로 선택하며 법령 ID를 중복시키지 않는다.

출처형 질문은 법령명 질문 80개와 조문·상황 질문 160개다. 질문 생성 모델이
참조 답변을 원문에서 연속 문자열로 정확히 복사했는지 검사한다. 실패한 경우
해당 법령·조문 이름을 찾는 질문으로 대체하고 `article_subject_fallback`으로 표시한다.
400문항의 검증 통과 참조 답변은 131개다. 전문가 검증 여부는 모두 false다.

법령명만 요청하는 질문에 임의의 특정 조문을 유일한 정답으로 지정하면 지표가
왜곡된다. 따라서 법령 적중률은 출처형 240개, 정확한 출처 조문 적중률은 참조
답변 검증을 통과한 131개에만 산출한다. 나머지 질문은 지연, 성공률, HITL,
응답 특성 및 반복 대조군 일치도에 사용한다. 라벨은 불완전한 silver known-item
라벨이다. 다른 정답 문서가 존재할 수 있어 전체 관련 문서 Recall로 해석할 수 없다.

예비셋 24문항에서 정확한 조문 평가가 가능한 질문은 10개다. 이 부분집합에서
raw → 인증 복구의 Hit@1은 0.60→0.80, MRR@20은 0.731→0.883이었다.
세 가지 재정렬 입력은 동일한 결과여서 단순한 기존 본문 입력을 종단 조건으로
선택했다. 작은 예비셋 결과는 본 결과의 정확도 주장에 합산하지 않는다.

## 반복과 측정

- 준비 추출: 400문항을 2회 실제 실행하여 동일 서빙의 반복 변동을 측정한다.
- 검색 재정렬: 첫 준비 결과를 고정하고 400문항 × 3회 실제 검색 및 4조건 재정렬.
  질의마다 조건 순서를 회전한다. 모델 치환이나 정답 라벨을 검색 입력에 사용하지 않는다.
- 종단 SSE: 400문항 × 2회 × 3조건, 동시성 4, 8문항 블록의 조건 순서를 회전·반전.
  조건 간 요청이 겹치지 않게 한다. 매 요청은 새로운 세션을 사용한다.
- 일반 JSON `/api/generate`는 SSE와 다른 코드 경로이므로 별도 결과로 기록한다.
  이 경로의 실험 규모·반복 수는 결과 파일의 실제 완료 건수로 표시한다.
- 첫 progress 이벤트와 첫 답변 token은 구분한다. TTFT는 첫 비어 있지 않은
  token 이벤트까지, 전체 지연은 응답 스트림 종료까지다.
- 측정 클라이언트와 별도 앱은 .53에서 실행한다. .52의 실제 배포 CPU·Nginx·
  브라우저까지 포함한 운영 SLA 실험은 아니며, .52→.53 네트워크는 별도 측정한다.
- warmup은 조건당 2개로 별도 제외한다. 재개 시 완료 행은 재실행하지 않는다.
- 서빙 KV prefix cache를 비우지 않는 warm 조건이다. 앞선 추출 실험도 같은
  질문을 사용했으므로 cold-start나 완전히 처음 보는 질의 성능으로 해석하지 않는다.
- HTTP 200, SSE done, 내부 LLM/리랭커/가드레일 상태는 서로 다른 지표다.
  실패를 0초나 완전 일치로 대체하지 않는다. 빈 참조의 Recall은 미정이다.
- 추론 내용은 출력하거나 저장하지 않는다. 시간·토큰 사용량·추론 문자 수만
  계측하며, 최종 답변과 입력 프롬프트는 운영자 전용 디렉터리에 보관한다.

최소 주 분석: 평균, p50/p95/p99, TTFT, 출처 법령·조문 Hit@1/5/20와 MRR@20,
응답에 출처 문서가 포함되는 비율, 대조군 반복과 조건 간 문서 일치도.
API가 최종 laws를 item_id로 정렬하기 때문에 그 순서를 검색 Top-1으로 해석하지
않는다. 검색 순위는 재정렬 직후 별도 trace에서 측정한다.

반복 관측은 질문별 평균으로 묶은 뒤 질문 단위 bootstrap 4,000회로 95% CI를
구한다. 속도는 평균 시간의 비율이다. 조문 Hit@1의 McNemar 검정은 첫 반복의
질문별 불일치 쌍을 한 번씩만 사용한다. 반복 실행을 독립 표본으로 부풀리지 않는다.
세 재정렬 후보와 raw의 비교에는 Holm 다중비교 보정도 함께 보고한다.
공유 GPU의 외부 부하는 완전히 통제할 수 없으므로 원인별 미세 차이는 제한적으로
해석하며 GPU 상태와 모델 프로세스 구성을 함께 기록한다.

## 선행연구와 기술적 위치

이 연구의 후보 기여는 새로운 speculative decoding 알고리즘 자체가 아니라,
검색어 출력에 민감한 시스템에서 단계별 의미 계약과 사용자 지연을 함께 검증하는
실증적 방법이다. 결과가 지지하지 않는 조건은 실패한 ablation으로 보고한다.

- [vLLM speculative decoding](https://docs.vllm.ai/en/latest/features/speculative_decoding/):
  분포 보존과 실행별 bitwise 동일성을 구분해야 한다. 이전 392/400 동일 결과만으로
  불일치가 전부 비결정성이라고 단정할 수 없다.
- [vLLM automatic prefix caching](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/):
  공유 prefix의 prefill을 재사용하는 방법이며, 긴 decode나 앱 내부 전송 대기를
  직접 해결하는 기술은 아니다.
- [Speculative RAG (2024)](https://arxiv.org/abs/2407.08223): 작은 전문 모델의 초안과
  큰 모델의 검증을 결합한다. 여기서의 준비 단계 중첩은 동일 모델·동일 입력을
  사용하며, 분류 결과가 허용하는 경로에서만 정확한 입력 일치 후 소비한다.
- [Lost in the Middle (2023)](https://arxiv.org/abs/2307.03172): 긴 문맥에서 위치에
  따른 성능 차이를 보고한다. 이 연구에서는 긴 본문 앞부분만 보는 재정렬의
  대안으로 질의 관련 구간을 검증하지만 개선을 보장하지 않는다.
- [OpenSearch RRF](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/rrf/):
  점수 정규화에 의존하지 않는 융합 대안이다. 공식 벤치마크도 항상 우월함을
  보장하지 않으므로, 본 실험에서는 임의로 기존 하이브리드를 교체하지 않는다.

## 추가 검증의 한계

전문가 relevance gold 및 법률 답변의 사실성·유용성 gold는 사람이 작성해야 한다.
LLM 심사는 자동 평가로 따로 표시한다. GPU가 모두 상주 서비스에 사용되고 있어
31B n-gram 파라미터 sweep·tensor parallelism·서빙 패키지 업그레이드는 이번
비중단 앱 실험에서 수행했다고 주장하지 않는다. 인위적 대기 제거의 화면 렌더링
영향은 실제 프런트엔드 검증이 필요하다. API 시험만으로 UI 회귀 없음이 입증되지는 않는다.

## 종단 실행 뒤의 탐색적 원인 분리

다음 실험은 주 종단 실험 실행 중 추가한 탐색적 분석이다. 주 조건을 고르는
용도로 사용하지 않으며, 본 측정이 끝난 후 순차 실행하여 GPU 경합을 추가하지 않는다.

국가 해석 CPU 감사와 국가만 보정하는 검색 대조군은 두 번째 SSE 실행 중
관찰한 출처 국가 불일치에 따라 추가했다. 따라서 사전 가설 검증이 아니라
관찰된 오류의 탐색적 원인 분리다. 주 종단 조건과 원 질문 보존 알고리즘은
이 발견 후에도 변경하지 않았다.

- 400문항 × 1회 잘림 규칙 민감도 검사: 고정한 첫 추출 결과로 새 후보를 찾은 뒤,
  같은 후보에서 본문 접두부와 원 코드의 strip·말줄임표 규칙을 비교한다. 인증은
  두 재정렬 조건 모두 정상이며, 이 검사는 종단 주 조건을 변경하지 않는다.
- 같은 baseline 생성 입력을 고정한 60문항 × 3조건 × 2회: 프록시/기본 추론,
  직접 연결/기본 추론, 직접 연결/낮은 추론량. 검색·문서 선별 차이를 배제한
  upstream 생성 대조군이다. 이 단계의 TTFT는 API TTFT가 아니다.
- 실제 입력 delta를 이용한 전송 helper 재생: 원래 5문자 청크·20ms 지연과 즉시
  전달의 시간 및 문자 동일성을 비교한다. 전체 답변을 임의의 한 청크로 합쳐
  원래 지연을 과대 추정하지 않는다. GPU 생성이나 브라우저 렌더링 실험은 아니다.
- 400문항 × 4조건, 1회 검색 전용 비교: 기존 추출, 원 질문 그대로 검색,
  원 질문·기존 추출의 병렬 검색 후보 합집합(RRF 후 재정렬), 작은 모델 추출.
  원 질문 검색은 질문에 명시된 유일한 국가명만 결정적으로 인식하며, 라벨이나
  출처 ID를 입력으로 사용하지 않는다. 재정렬 전 후보 ID도 기록해 출처 후보
  포함 여부와 재정렬 후 Top-20 포함 여부를 구분한다. 이 경로는 의도 판별·가드레일·대화 이력·
  답변 생성을 포함하지 않으므로 전체 서비스 대체 또는 종단 배속으로 해석하지 않는다.
- 국가만 보정하는 400문항 × 2회 새 검색: 첫 추출의 검색어·키워드·국가 목록을
  고정하고, 질문에 명시된 유일한 긴 관할명만 국가 값에 적용한다. 복수 관할이면
  기존 값을 유지한다. 두 조건 모두 같은 인증 정상 본문 재정렬을 사용한다.
  국가 값 변경과 원 질문 검색 표현 변경의 효과를 구분하기 위한 별도 대조군이다.
- 131개 출처형 질문의 첫 종단 반복 답변을 조건명을 숨겨 별도 phi-4 모델로 평가:
  관련성과 제시 근거의 뒷받침을 각각 0–2점으로 평가한다. 단일 자동 심사기의
  판단은 법률 전문가의 사실성 판정이나 절대 정확도 증명이 아니다.

자동 답변 평가 완료 후에는 공통 저득점 5문항에서 개인정보 경고를 관찰해
추가 읽기 전용 진단을 정의했다. 400개 기존 첫 회차 응답과 고정 소스의
국가와 무관한 안전 분류 매핑·PII 정규식을 CPU에서 감사한다. 마지막 검색 시간
측정까지 끝난 뒤 공통 5문항만 원래 분류 입력 그대로 다시 호출해 원시 카테고리
토큰을 확인한다. 이는 결과를 본 뒤 선택한 오류 진단이며 사전등록된 가설 검정이나
새로운 가드레일 정확도 평가가 아니다. 원 실험 응답·점수·차단 정책은 변경하지 않는다.
